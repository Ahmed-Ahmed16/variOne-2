## Key invariants — DO NOT regress
- **NEVER touch `varione-stable`** — it is the MVP-done, everything-working branch
  (user directive). All UI work stays on `ui-revamp`.
- **Naming is `Vemo` (one e), everywhere** — symbols, theme keys (`vemo_*`), asset
  filenames, folder `VariOne_Vemo`. The earlier `Veemo` spelling was a typo; do not
  reintroduce it. See [src/modules/varione/ui/vemo_status.h](src/modules/varione/ui/vemo_status.h).
- **Theme PNGs must be ≤160 px wide** or the PNG decoder line buffer overflows
  ([src/core/display.cpp](src/core/display.cpp), `MAX_IMAGE_WIDTH`). The 320 px scifi
  theme will crash — reference only, never load.
- **`showVemoStatus()` must degrade gracefully**: no `vemo_*` image, or a missing/
  corrupt `.bin`, falls back to the stock Bruce band (`displayTextLine/Success/Error`).
  Keep that path. [src/modules/varione/ui/vemo_status.cpp](src/modules/varione/ui/vemo_status.cpp).
- **Decision 4**: status text never sits over Vemo's face — scan = small head +
  adjacent text; success/error = full-screen art + BOTTOM band.
- **Menu hide is name-based** ([src/core/main_menu.cpp](src/core/main_menu.cpp)
  `isBoardHiddenMenu`: Ethernet/GPS/LoRa/FM). Brittle on any `getName()` rename.
- **lib_deps changes need a clean build** (stripping them once corrupted the `.pio`
  variant cache) — see plan Decision 1.
- SubGHz saves stay on LittleFS; IR/NFC/WiFi stay on SD ([[subghz-littlefs]]).
